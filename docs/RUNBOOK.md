# 上市櫃企業實習雷達維運手冊

## 每日流程

GitHub Actions 使用 `.github/workflows/daily_pipeline.yml`，在 `main` 分支執行。排程時間與次數由該檔控制；修改前須另行核准。流程依序執行隔離測試、現有公開資料檢查、104 抓取、Gemini 分析、再次檢查、資料備份與備份檢查、Git 推送，最後才同步 Google Sheets。Sheets 同步若失敗，Git 資料已更新，需檢查並補同步。

手動補跑：在 GitHub Actions 選擇 `Daily 104 Internship Pipeline`，選 `main` 後執行。補跑前先確認前次失敗原因與 Gemini 額度，避免重複消耗配額。不要直接修改正式 `data/data.json` 來跳過失敗。

本機預覽可用 `python -m http.server 8000`，只提供前端頁面；不會執行每日流程。本機批次入口為 `run_daily.ps1`，會拒絕在資料已變更、分支不符或 Git 尚未同步時繼續。請先審查既有變更，不要直接清除它們。

## Gemini 額度與分析

模型由 `GEMINI_MODEL` 指定；目前工作流程配置為 `gemini-3.6-flash`。`GEMINI_API_KEY` 僅放在環境變數或 GitHub Actions Secret。每輪有請求量與時間上限；月度額度耗盡時立即停止、維持待分析狀態並讓流程失敗。查看 Google AI Studio 的專案用量與帳務限制，再決定何時補跑；增加重試次數不能解決月度額度耗盡。

104 原始職缺說明暫存於系統暫存資料夾，位於網站根目錄之外；公開 `data/data.json` 只保存來源基本欄位及已完成的分析。分析只處理最近 7 天首次收錄的職缺；暫存原文遺失或超過時間窗時，不會自動回抓舊職缺。請勿將原文暫存複製回網站根目錄或提交到 Git。

## 資料審核

新職缺的學歷條件未逐筆核實前不宣稱為學士要求。AI 整理的工作職責、摘要與課程需標示其性質。論壇連結只有人工確認與該職缺或雇主實習經驗有具體關聯的 Dcard/PTT 文章才可標記為 `*_verified: true`；搜尋頁與泛用討論頁不得發布。

公司對照可審核 `data/unmatched_companies.json`；新職缺只收錄上市櫃發行公司本身刊登者，不以母子公司關係替代實際雇主核對。提交前執行 `python -m unittest discover -s tests`、`python scripts/quality_gate.py`，並人工抽查新職缺的 104 原頁、狀態、學歷與分析內容。

## 故障與還原

104 搜尋第一頁為零、品質檢查失敗或 Gemini 額度耗盡時，停止發布並查看流程記錄。每日抓取預設只檢查近 7 天、最多 10 頁，連續 2 頁無近期刊登即停止；不會在每輪先刷新所有既有開放職缺，因此舊職缺的截止狀態不會每日重新確認。若搜尋端點或頁面異常，須區分 104 存取限制、端點格式與頁面結構變更。

備份由每日流程在推送前建立於 `backup/`。品質檢查會拒絕任何仍含 `raw_description` 的公開備份。2026-11-19 發布候選分支以當時最新遠端的 375 筆職缺為基準，清理公開資料、CSV 與 30 份備份；完整原檔與 62 筆待分析原文保存在專案目錄外的私人封存。遠端在候選版建立後新增的 11 月 19 日備份已另行封存並清理。封存未提交至 Git；舊 Git 歷史仍保有當時內容。還原前先比對 Git 歷史與目標備份、確認需要保留的新職缺，再審查差異並透過正常變更流程提交至 `main`。勿直接覆蓋未審查的正式資料。
